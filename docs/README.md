# yosage-dev-harness の使い方

このディレクトリは、プラグイン `yosage-dev-harness` の**使い方の流れ**を説明する。
入れ方・設定項目・機能の一覧はリポジトリ直下の [README](../README.md) にある。ここでは
「何をどう頼めば、何が起きて、人はどこで何をするか」を順に説明する。

## 読む順

初めて使うときは、上から順に読む。

| ページ | 内容 |
|---|---|
| [はじめての1件](getting-started.md) | 小さな修正を1件頼み、PR をマージするまでの通しの流れ |
| [変更の規模ごとの流れ](workflows.md) | 自明な小修正・追跡が要る単発・設計判断が要る単発・Epic の4つの進め方と、それぞれで打つコマンド |
| [Epic の進め方](epic.md) | 大きな変更を、計画・起票・実装・レビュー・完了の順に進める |

## この文書の前提

- 導入（`claude plugin marketplace add` / `claude plugin install` / `/yosage-dev-harness:setup`）は
  済んでいる。まだなら [README のセットアップ](../README.md#セットアップ) を先に行う。
- スキルは `/yosage-dev-harness:<スキル名>` の形で打つ。サブエージェントは
  `yosage-dev-harness:<エージェント名>` の名前で呼ばれる（人が打つものではなく、Claude が
  作業を任せるときに使う）。一覧は [README の機能カタログ](../README.md#機能カタログ自動生成)。
- 「人がやること」は各ページで**太字**にしてある。それ以外は Claude が進める。
- 迷ったら `/yosage-dev-harness:harness-help` で、やりたい作業から使うスキルを引ける。

## 拡張: リーダーハーネス

複数のリポジトリや案件をまたいで統制する用途向けに、拡張として `yosage-dev-leader-harness`
（リーダーハーネス）がある。**この本体（`yosage-dev-harness`）が入っていることが前提**で、
本体の使い方は上の各ページで完結する。リーダーハーネスの使い方は、そちらのリポジトリで
別に説明している。
