# design-doc — 作る前に、設計を issue で詰める

非自明な変更は、いきなり実装せず**設計を issue に書いて合意**を取る。目的は「手戻りを減らす」「意図を残す」「引き継げる」の3点。
**検討中の設計は `.docs/` に置かない**（`.docs/` は決定済みの正本だけ）。置き場の正本は ルール `doc-placement`。

## いつ使うか
- 新機能、データモデル変更、外部依存の追加、複数ファイルにまたがるリファクタ
- 「やり方が一通りに決まらない」「後戻りが高くつく」と感じたとき
- 逆に、1ファイルの自明な修正には使わない（過剰設計を避ける）

## なぜ issue に書くか（ファイルでなく）
- **引き継げる**: self-contained な issue は、別セッション/別人がそのまま続けられる（issue-first）。
- **`.docs/` を汚さない**: 未決定の RFC ファイルが正本に混ざらない。
- **議論が残る**: 検討・代替案・決定がコメントとして GitHub に資産化される。

## 進め方
1. **接地（recall）** — 関連コードを `Explore`/`Grep` で読み、過去の判断を [[recall-knowledge]] で引く（[[grounded-design]]）。憶測で書かない。
2. **設計 issue を立てる** — 下のテンプレを本文に `gh issue create`（[[issue-create]] の self-contained 規律に従う。種別ラベルを付与＝多くは `feat`/`refactor`）。設計を書いたファイルを `.docs/` の中に作ることは**しない**。
3. **代替案を最低2つ** — 採用案だけでなく、捨てた案と「なぜ捨てたか」を残す。これが後で効く。
4. **未解決点を議論** — Open Questions を出し、`AskUserQuestion` や issue コメントで詰める。決まったら本文を更新する。
5. **合意 → 蒸留 → 実装** — 決まったら:
   - **正本へ**: 製品/アーキに効く決定は `.docs/`（architecture 等）へ反映。
   - **決定へ**: 再利用可能な判断/ADR は `.claude/knowledge/` へ [[capture-learning]]（下記）。
   - **実装へ**: [[issue-implement]] で実装し、PR は `Closes #<この issue>`。

## 設計 issue の本文テンプレート

```markdown
## 背景 / 課題
何を、なぜ。今のままだと何が困るか。

## ゴール / 非ゴール
- ゴール: …
- 非ゴール: （あえてやらないこと。スコープの境界）

## 制約
既存アーキ・性能・互換性・期限など、解を縛る条件。

## 案
### 採用案
何を、どう。図やデータモデル、影響範囲。
### 検討した代替案
- 案B: … / 不採用理由: …
- 案C: … / 不採用理由: …

## 影響 / リスク
壊れうる箇所、移行、ロールバック手順。

## テスト方針
何をどう検証すれば「正しい」と言えるか。

## Open Questions
- [ ] …
```

> **Status は issue の状態で表す**: open=議論中 / closed=決定（→ 実装 PR が `Closes #`）or 見送り（`wontfix` 等で手動クローズ。見送り理由は必要なら [[capture-learning]] で残す）。別ファイルの `Status:` 行は持たない。

## 確定したら知見を残す（knowledge loop の後半）
設計が決まったら、その過程で得た**再利用可能な知見**を [[capture-learning]] で `.claude/knowledge/` に蓄積する
（設計 issue はこの機能の決定・代替案を残すが、横断的に効く**判断基準・パターン・制約・落とし穴**は別途 capture しないと知識ベースに残らない）。
- 例: 「この種の制約があるとき X を選ぶ」「この pattern は他にも一般化できる」「この前提は見落としやすい」。
- capture は **設計した本人**が回す（誰が回すか・省略不可は ルール `knowledge`）。

## 原則
- **小さく速く**: 完璧な文書より、合意できる最小の issue。
- **トレードオフを言語化**: 「Aを取ってBを捨てた」を明示するのが設計の価値。
- **置き場を守る**: 未決定を `.docs` 正本に混ぜない（`.docs`/issue/knowledge の振り分けは ルール `doc-placement`）。
