# project-profile（不変条件）

「導入先固有の座標」と「harness 由来の横断ルール」は所有者が違う。書き込み先を取り違えないことになっている。

- **導入先固有の座標**（スタック・ビルド/検証コマンド・ワークスペースのトポロジ・repo ごとの取扱い）は
  **`.claude/rules/<名前>/profile.md`** に置くことになっている。これは**利用者所有**であり、プラグインの
  有効化時にも、マーケットプレイスの更新時にも harness が自動生成・上書きすることはない。既に `.docs/` に正本がある事項（例: ドメイン語彙は `glossary` skill、
  ディレクトリ構成/アーキテクチャは `document-architecture` skill）は profile に重複させない決まりになっている。
- **base ブランチの宣言**も導入先固有の座標の一種として profile.md に書く。書式は
  `` - **base ブランチ: `<名前>`** `` の1行。GitHub の既定ブランチと実際の取り込み先が食い違う導入先でだけ書けばよい
  （一致していれば書かなくてよく、書いてあっても害は無い）。宣言はモデルが読み、`yosage-dev-harness-base-branch --declared <名前>`
  に渡す（スクリプトは profile の文章を解析しない。解決の順は [[pr-loop]]）。
- **実装の着火の委譲**も導入先固有の座標の一種として profile.md に書く。書式は
  `` - **実装の着火の委譲: `単発 issue`** `` の1行（base ブランチの宣言と同じ流儀）。意味は「宣言した範囲（`単発 issue`＝
  Epic に属さない単発の issue）の実装 dispatch は、メイン（オーケストレーター）が着火してよい」。書式どおりでなければ、
  宣言が無いものとして扱う（従来どおり人が引く）。対象の範囲と対象外（Epic の Sub-issue・Epic 全体の実装・一括起票・Epic 級の
  討議への入場・マージ）は [[implement-routing]] が正本（ここでは再記述しない）。profile はモデルも編集しうるので、
  「人が書いた宣言に限る」ことの担保は文面だけである（既知の限界）。
- **検証時排他資源**（並列実装で検証コマンドの一部が奪い合う単一インスタンス資源）も導入先固有の座標の一種として
  profile.md に書くことになっている。書く内容は抽象カテゴリ（「シミュレータ」等）ではなく**具体的な単一インスタンス資源**
  （固定ポート番号・特定 UDID/AVD・共有ビルドディレクトリ・keychain 等）に限られる。書く前に**隔離できないか**
  （エージェントごとに動的ポート・使い捨てインスタンスへ分離できないか）を先に検討し、隔離不能と判定した
  ものだけをここに記載することになっている。この項目は [[orchestrate-parallel]] の共有資源語彙（DB/ポート/compose スタック）
  と同列に扱われる（新語は作らない・[[naming]]）。
- **プロセス復旧手順**（会話不可能な生バックグラウンドプロセスを [[agent-watchdog]] の判定で kill した後に
  必要な後処理）も導入先固有の座標の一種として profile.md に書くことになっている。書く内容はツール/プロジェクトごとに
  異なる具体的な手順（例: 「モバイル UI 自動操作 CLI の kill 後にシミュレータを再起動する」）に限られる。
  `agent-watchdog.md` 側はこの手順を再記述せず、宣言があればそれに従うという参照だけを持つ。
- **harness 由来の横断ルール**（不変条件）はプラグインの中にあり、セッション開始時（`SessionStart`）と
  サブエージェント起動時（`SubagentStart`）のフックで1ファイルずつ注入されることになっている。導入先
  （`.claude/`）には置かれない。ここに導入先固有の記述を書いても注入されず、次に反映されることもない
  （置き場を取り違えているだけであり、書いた内容自体は消えない）。導入先固有の記述は上記の
  `.claude/rules/<名前>/profile.md` に書く決まりになっている。
- **profile.md を起こす／鮮度チェックする手段**: 人間が明示的に起動する `document-profile` skill が
  対象を調査して下書きを作り、人間の確認を経て書き出すことになっている（[[document-profile]]）。
  プラグインの有効化・マーケットプレイスの更新はこの skill を自動実行しない＝**着火は常に人間トリガ**
  であり、書き出した後は harness が後から上書きすることはない（利用者所有という核心は変わらない）。
