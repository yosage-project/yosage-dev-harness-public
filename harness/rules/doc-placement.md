# doc / 設計の置き場（不変条件）

設計・ドキュメントは性質で置き場を分けることになっている。要は **`.docs/` に未決定のメモは置かない**決まりになっている。

| 段階 | 置き場 |
|---|---|
| **検討中の設計**（未決定・議論中・引き継ぎ得る） | **issue に書いて議論**（[[design-doc]]） |
| **決定 / 判断記録（ADR）** | **`.claude/knowledge/`**（[[capture-learning]]） |
| **正本**（製品/アーキの真実・決定済み/凍結寄り） | **`.docs/`**（`architecture` / `standards` / `glossary` を含む） |
| **揮発的な思考** | 会話のまま（残さない） |

- **`.docs/` = 正本だけ**: 未決定の RFC/メモは置かない決まりになっている。議論は issue で行い、決まったら `.docs`（正本）と `.claude/knowledge`（決定）へ蒸留して issue を閉じることになっている。
- 正本には「生きてる正本」＋「日付つき凍結記録」が入りうる（凍結記録は **Status/日付を明記**して living 正本と区別し、更新しない決まりになっている）。
- `.epic_docs/` は Epic の計画作業メモという位置づけである（issue へ抽出する下書き。`.docs` 正本ではない）。
- ワークスペース直下 `<workspace>/.docs/` は**別物＝横断/一時置き場**として扱われている（repo 成果物からは参照しない。issue 規律は [issue-discipline](issue-discipline.md)）。
